# Linux 용어 정리

## 사용자와 권한

### 사용자

Linux에서 명령을 실행하고 파일을 소유하는 주체다.

B1-1에서는 다음 사용자를 만든다.

- `agent-admin`: 앱 실행과 운영 담당
- `agent-dev`: 스크립트와 설정 관리 담당
- `agent-test`: 테스트 담당

### 그룹

여러 사용자에게 같은 권한을 주기 위한 단위다.

B1-1에서는 다음 그룹을 사용한다.

- `agent-common`: 세 계정이 함께 접근하는 공유 그룹
- `agent-core`: 운영 핵심 파일에 접근하는 제한 그룹

### UID

User ID의 약자다. Linux가 사용자를 내부적으로 구분하는 숫자다.

### GID

Group ID의 약자다. Linux가 그룹을 내부적으로 구분하는 숫자다.

### 주 그룹

사용자가 기본으로 속하는 그룹이다. 파일을 만들 때 기본 그룹으로 사용될 수 있다.

### 보조 그룹

사용자가 추가로 속하는 그룹이다. `usermod -aG`로 추가한다.

### root

Linux의 최고 관리자 계정이다. 모든 파일과 설정에 접근할 수 있으므로 앱을 root로 실행하지 않는 것이 원칙이다.

### sudo

일반 사용자가 일시적으로 관리자 권한으로 명령을 실행하게 해주는 도구다.

## 파일과 디렉터리

### 홈 디렉터리

사용자별 기본 작업 공간이다.

예:

```text
/home/agent-admin
```

### 소유자

파일이나 디렉터리를 소유한 사용자다.

### 소유 그룹

파일이나 디렉터리에 연결된 그룹이다. 같은 그룹에 속한 사용자에게 권한을 줄 수 있다.

### others

소유자도 아니고 소유 그룹에도 속하지 않는 나머지 사용자다.

### 권한

파일이나 디렉터리에 대해 읽기, 쓰기, 실행을 허용할지 정하는 규칙이다.

- `r`: read, 읽기
- `w`: write, 쓰기
- `x`: execute, 실행 또는 디렉터리 진입

### ACL

Access Control List의 약자다. 기본 소유자/그룹/others 권한보다 더 세밀하게 접근 권한을 줄 때 사용한다.

## 프로세스와 네트워크

### 프로세스

실행 중인 프로그램이다. 앱이 실행되면 하나 이상의 프로세스가 생긴다.

### PID

Process ID의 약자다. Linux가 프로세스를 구분하는 숫자다.

### 포트

네트워크 프로그램이 요청을 받는 번호다. B1-1 앱은 `15034` 포트를 사용한다.

### LISTEN

프로그램이 특정 포트에서 요청을 받을 준비가 된 상태다.

`ss -tulnp`에서 `LISTEN`이 보이면 해당 포트가 열려 있다는 뜻이다.

### localhost

현재 자기 자신을 가리키는 주소다.

```text
127.0.0.1
```

### 방화벽

서버로 들어오는 네트워크 접근을 허용하거나 차단하는 보안 장치다.

B1-1에서는 SSH용 `20022/tcp`, 앱용 `15034/tcp`만 허용한다.

## 로그와 자동화

### 로그

시스템이나 앱에서 발생한 일을 시간순으로 기록한 파일이다.

예:

```text
/var/log/agent-app/monitor.log
```

### exit code

명령이 끝난 뒤 성공 또는 실패를 나타내는 숫자다.

- `0`: 성공
- `1` 이상: 실패

### cron

정해진 시간마다 명령을 자동 실행하는 Linux 스케줄러다.

### crontab

cron에 등록할 작업 목록이다.

예:

```text
* * * * * /home/agent-admin/agent-app/bin/monitor.sh
```

### logrotate

로그 파일이 너무 커지지 않도록 회전, 압축, 보관 개수를 관리하는 도구다.

## Shell과 스크립트

### 터미널

명령어를 입력하고 결과를 확인하는 화면 또는 프로그램이다.

macOS Terminal, VS Code 터미널, OrbStack Ubuntu shell이 모두 터미널 역할을 할 수 있다.

### shell

사용자가 입력한 명령을 해석해서 운영체제에 전달하는 프로그램이다.

B1-1 스크립트는 주로 Bash shell을 기준으로 작성한다.

### Bash

Bourne Again Shell의 약자다. Linux에서 널리 쓰는 shell이다.

`monitor.sh`, `report.sh`, `setup-*.sh`는 Bash 문법으로 작성되어 `bash -n`으로 검사한다.

### shebang

스크립트 첫 줄에서 어떤 해석기로 실행할지 지정하는 줄이다.

예:

```bash
#!/usr/bin/env bash
```

이 줄이 있으면 실행 권한이 있는 스크립트를 직접 실행할 때 Bash로 해석할 수 있다.

### shell script

shell 명령을 파일에 순서대로 적어 자동 실행할 수 있게 만든 파일이다.

B1-1에서는 계정 생성, 디렉터리 권한 설정, 방화벽 설정, 관제, 로그 정리를 스크립트로 자동화한다.

### 환경 변수

프로그램이 실행될 때 참고하는 이름과 값의 쌍이다.

예:

```text
AGENT_HOME=/home/agent-admin/agent-app
AGENT_PORT=15034
```

앱과 스크립트가 같은 경로와 포트 값을 사용하게 해준다.

### PATH

명령어를 입력했을 때 실행 파일을 찾는 디렉터리 목록이다.

cron은 일반 터미널보다 PATH가 짧을 수 있으므로 운영 스크립트에서는 절대 경로를 쓰는 편이 안전하다.

### 인자

명령이나 스크립트 뒤에 전달하는 값이다.

예:

```bash
scripts/setup-firewall-ufw.sh --apply
```

여기서 `--apply`가 인자다.

### 옵션

명령의 동작을 바꾸는 인자다. 보통 `-l`, `--apply`처럼 하이픈으로 시작한다.

### stdout

표준 출력이다. 명령이 정상 결과를 출력하는 통로다.

### stderr

표준 에러다. 명령이 오류 메시지를 출력하는 통로다.

### stdin

표준 입력이다. 명령이 데이터를 입력받는 통로다.

파이프를 사용하면 앞 명령의 stdout이 뒤 명령의 stdin으로 전달된다.

### pipe

앞 명령의 출력을 뒤 명령의 입력으로 넘기는 연결이다.

예:

```bash
ps -ef | grep agent
```

### redirection

명령의 입력이나 출력을 파일로 돌리는 기능이다.

- `>`: 파일을 새로 쓰거나 덮어쓴다.
- `>>`: 파일 뒤에 누적한다.
- `2>&1`: stderr를 stdout과 같은 위치로 보낸다.

### file descriptor

프로세스가 파일이나 입출력 통로를 구분하는 번호다.

- `0`: stdin
- `1`: stdout
- `2`: stderr

cron 로그에서 `2>&1`을 쓰면 오류 메시지도 같은 로그 파일에 남길 수 있다.

## 서비스와 보안

### SSH

Secure Shell의 약자다. 원격 서버에 안전하게 접속하기 위한 프로토콜이다.

B1-1에서는 기본 포트 22 대신 `20022/tcp`를 사용한다.

### sshd

SSH daemon의 줄임말이다. SSH 접속 요청을 받는 서버 프로세스다.

`ss -tulnp`에서 sshd가 `20022` 포트로 LISTEN 중인지 확인한다.

### daemon

사용자 화면에 직접 보이지 않고 백그라운드에서 계속 실행되는 서비스 프로세스다.

`sshd`, `cron` 같은 프로그램이 대표적인 daemon이다.

### systemd

Ubuntu에서 서비스를 시작, 중지, 재시작, 자동 실행하도록 관리하는 시스템 관리자다.

`systemctl status ssh`처럼 서비스 상태를 확인할 때 사용한다.

### UFW

Uncomplicated Firewall의 약자다. Ubuntu에서 방화벽 규칙을 쉽게 설정하는 도구다.

B1-1에서는 `20022/tcp`, `15034/tcp`만 허용한다.

### firewalld

일부 Linux 배포판에서 사용하는 방화벽 관리 서비스다.

B1-1 기본값은 UFW지만, 다른 환경에서는 firewalld 상태를 확인할 수 있다.

### inbound

외부에서 서버로 들어오는 네트워크 연결이다.

방화벽에서는 불필요한 inbound 연결을 기본 차단하는 것이 안전하다.

### outbound

서버에서 외부로 나가는 네트워크 연결이다.

패키지 설치나 업데이트가 필요하므로 B1-1 UFW 정책에서는 outbound를 기본 허용한다.

### attack surface

공격자가 접근하거나 악용할 수 있는 노출 지점의 범위다.

불필요한 포트를 닫으면 attack surface를 줄일 수 있다.

## 파일 권한 세부 용어

### mode

파일 권한을 숫자나 문자로 표현한 값이다.

예:

```text
750
0640
2770
```

### setgid

디렉터리에 설정하면 그 안에서 새로 만들어지는 파일이나 디렉터리가 부모 디렉터리의 그룹을 상속하게 하는 권한 비트다.

B1-1에서는 `upload_files`, `api_keys`, `/var/log/agent-app`의 그룹 일관성을 유지하는 데 유용하다.

### traverse 권한

디렉터리 안으로 통과할 수 있는 실행 권한이다.

파일 목록을 보는 읽기 권한과 다르게, `--x`는 경로를 알고 있을 때 하위 디렉터리로 들어가는 최소 권한이다.

### umask

새 파일이나 디렉터리를 만들 때 기본 권한에서 빼는 값이다.

운영 스크립트에서는 umask에만 의존하지 않고 `chmod`, `install -m`, `create` 옵션으로 권한을 명확히 지정하는 편이 안전하다.

## 관제와 로그

### timestamp

이벤트가 발생한 시각을 나타내는 값이다.

예:

```text
2026-05-27 14:10:00
```

monitor.log는 timestamp를 앞에 붙여 시간순으로 상태를 추적한다.

### threshold

경고나 장애 판단에 사용하는 기준값이다.

B1-1에서는 CPU 20%, MEM 10%, DISK_USED 80%를 경고 기준으로 사용한다.

### CPU 사용률

프로세스나 시스템이 CPU를 얼마나 사용하는지 나타내는 비율이다.

### MEM 사용률

프로세스나 시스템이 메모리를 얼마나 사용하는지 나타내는 비율이다.

### DISK_USED

디스크가 얼마나 사용 중인지 나타내는 비율이다.

B1-1에서는 root partition `/`의 사용률을 수집한다.

### root partition

Linux 파일시스템의 시작점인 `/`가 들어 있는 파티션이다.

이 공간이 가득 차면 로그 기록, 패키지 설치, 서비스 실행에 문제가 생길 수 있다.

### log rotation

현재 로그 파일을 일정 기준으로 다른 이름으로 넘기고 새 로그 파일을 쓰게 하는 관리 방식이다.

### archive

오래된 파일을 장기 보관용 위치로 옮겨 둔 것이다.

B1-1 보너스에서는 오래된 `.log`를 `.gz`로 압축해 `/var/log/monitor/agent-app/archive/`에 보관한다.

### compression

파일 크기를 줄이는 작업이다.

로그 파일은 텍스트라 gzip 압축 효과가 큰 편이다.

### dry-run

실제 변경을 하지 않고 어떤 작업이 일어날지 미리 보여주는 실행 방식이다.

방화벽이나 logrotate처럼 시스템에 영향을 주는 작업을 적용하기 전에 검토할 때 유용하다.

## 실행 파일과 호환성

### 바이너리

컴퓨터가 직접 실행할 수 있는 형태로 빌드된 파일이다.

B1-1 제공 앱의 `agent-app-linux-x86`, `agent-app-linux-arm64` 같은 파일이 바이너리다.

### 아키텍처

CPU가 명령을 처리하는 구조다.

대표 예:

- `x86_64`: Intel/AMD 64비트 환경
- `arm64`: Apple Silicon, ARM 64비트 환경

현재 환경에 맞지 않는 바이너리를 실행하면 실행 오류가 날 수 있다.

### shared library

여러 프로그램이 함께 사용하는 공용 라이브러리 파일이다.

Linux 실행 파일은 glibc 같은 shared library에 의존할 수 있다.

### glibc

GNU C Library의 약자다. Linux 프로그램이 기본 시스템 기능을 사용할 때 의존하는 핵심 라이브러리다.

`GLIBC_2.38 not found` 오류는 실행 파일이 현재 OS보다 더 최신 glibc를 요구한다는 뜻일 수 있다.

### package

프로그램과 관련 파일을 설치하기 쉽게 묶어 둔 단위다.

Ubuntu에서는 `apt install`로 `openssh-server`, `ufw`, `logrotate`, `cron`, `acl` 같은 package를 설치한다.

### repository

패키지를 내려받는 저장소다.

`apt update`는 repository의 패키지 목록을 최신 상태로 갱신한다.
