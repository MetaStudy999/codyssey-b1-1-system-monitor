# 디렉터리와 권한 설정

## 이 단계의 목표

앱 홈, 업로드 디렉터리, API 키 디렉터리, 로그 디렉터리를 만들고 그룹별 권한을 설정한다.

## 왜 이 작업을 하는가?

업로드 파일은 세 계정이 협업할 수 있어야 하지만, API 키와 로그는 운영 핵심 정보이므로 `agent-core`만 접근해야 한다.

## 사전 확인

```bash
id agent-admin
id agent-dev
id agent-test
getent group agent-common
getent group agent-core
```

## 실행 명령어

```bash
sudo bash scripts/setup-dirs.sh
```

## 명령어 설명

스크립트의 기본 경로:

```text
AGENT_HOME=/home/agent-admin/agent-app
AGENT_UPLOAD_DIR=/home/agent-admin/agent-app/upload_files
AGENT_KEY_PATH=/home/agent-admin/agent-app/api_keys/t_secret.key
AGENT_LOG_DIR=/var/log/agent-app
```

권한 정책:

```text
upload_files: agent-common 그룹 읽기/쓰기
api_keys: agent-core 그룹만 접근
/var/log/agent-app: agent-core 그룹만 접근
```

`AGENT_HOME`은 `/home/agent-admin` 아래에 만들기 때문에 상위 홈 디렉터리의 탐색 권한도 중요하다. `scripts/setup-dirs.sh`는 `agent-core` 그룹이 `/home/agent-admin`을 통과만 할 수 있도록 ACL을 설정한다.

```text
/home/agent-admin: agent-core 그룹에 --x ACL 부여
```

이 ACL은 홈 디렉터리 목록을 읽는 권한이 아니라, `/home/agent-admin/agent-app` 하위 경로로 들어가기 위한 최소 탐색 권한이다.

## 기대 결과

필수 디렉터리가 생성된다.

```text
/home/agent-admin/agent-app
/home/agent-admin/agent-app/upload_files
/home/agent-admin/agent-app/api_keys
/home/agent-admin/agent-app/bin
/var/log/agent-app
```

키 파일이 생성된다.

```text
/home/agent-admin/agent-app/api_keys/t_secret.key
```

## 결과 확인 명령어

`agent-admin` 또는 `agent-core` 그룹에 속한 계정으로 확인한다. 현재 로그인 계정이 일반 Ubuntu 계정이라면 권한 정책 때문에 `Permission denied`가 나올 수 있으므로 `sudo`로 확인한다.

```bash
export AGENT_HOME=/home/agent-admin/agent-app

whoami
id
namei -l "$AGENT_HOME"

ls -ld "$AGENT_HOME"
ls -ld "$AGENT_HOME/upload_files"
ls -ld "$AGENT_HOME/api_keys"
ls -ld "$AGENT_HOME/bin"
ls -ld /var/log/agent-app
ls -l "$AGENT_HOME/api_keys/t_secret.key"
getfacl "$AGENT_HOME/upload_files"
getfacl "$AGENT_HOME/api_keys"
getfacl /var/log/agent-app
```

일반 계정에서 `ls: cannot access '/home/agent-admin/agent-app': Permission denied`가 나오면 다음처럼 권한 경로를 먼저 확인한다.

```bash
export AGENT_HOME=/home/agent-admin/agent-app
namei -l "$AGENT_HOME"
sudo namei -l "$AGENT_HOME"
```

`/home/agent-admin` 줄에 현재 계정이 통과할 권한이 없다면 정상적인 접근 차단이다. 증빙 출력만 필요하면 `sudo` 또는 `agent-admin` 실행 컨텍스트로 확인한다.

```bash
sudo ls -ld "$AGENT_HOME"
sudo ls -ld "$AGENT_HOME/upload_files"
sudo ls -ld "$AGENT_HOME/api_keys"
sudo ls -ld "$AGENT_HOME/bin"
sudo ls -ld /var/log/agent-app
sudo getfacl /home/agent-admin
sudo getfacl "$AGENT_HOME/upload_files"
sudo getfacl "$AGENT_HOME/api_keys"
sudo getfacl /var/log/agent-app
```

ACL이 빠져 있다면 다음 명령으로 보정한 뒤 다시 확인한다.

```bash
sudo setfacl -m g:agent-core:--x /home/agent-admin
getfacl /home/agent-admin
```

## README에 붙여넣을 증빙

`ls -ld`, `ls -l`, `getfacl` 출력 결과를 붙인다.

## 자주 발생하는 오류

- `Missing user`: `docs/02-계정-그룹-생성.md`의 스크립트 실행 방법 또는 직접 명령어 방법으로 계정/그룹을 먼저 생성한다.
- `/var/log/agent-app` 생성 실패: `sudo` 권한이 필요하다.
- `ls -ld "$AGENT_HOME"` Permission denied: 현재 계정이 `agent-core` 멤버가 아니거나 `/home/agent-admin` 탐색 권한이 없을 수 있다. `namei -l "$AGENT_HOME"`으로 어느 경로에서 막히는지 확인하고, 증빙은 `sudo` 또는 `agent-admin` 컨텍스트로 수집한다.
- 키 파일 내용이 다름: 기존 파일을 보존하도록 설계되어 있으므로 직접 확인한다.
