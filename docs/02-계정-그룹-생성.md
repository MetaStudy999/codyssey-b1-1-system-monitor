# 계정과 그룹 생성

## 이 단계의 목표

`agent-admin`, `agent-dev`, `agent-test` 계정과 `agent-common`, `agent-core` 그룹을 만든다.

## 왜 이 작업을 하는가?

운영자는 앱을 실행하고, 개발자는 스크립트를 관리하며, 테스트 계정은 공유 업로드 영역만 접근하게 만든다. 이것이 역할 기반 접근 제어의 기본이다.

## 사전 확인

Ubuntu에서 실행한다.

```bash
id agent-admin
id agent-dev
id agent-test
getent group agent-common
getent group agent-core
```

아직 생성 전이면 일부 명령은 실패하는 것이 정상이다.

## 실행 명령어

방법 1: 스크립트로 실행

```bash
sudo bash scripts/setup-users.sh
```

방법 2: 스크립트를 사용하지 않고 명령어로 직접 실행

아직 `scripts/setup-users.sh`를 실행하지 않았다면 아래 명령어로 같은 작업을 직접 수행할 수 있다.

```bash
sudo groupadd -f agent-common
sudo groupadd -f agent-core

getent passwd agent-admin >/dev/null 2>&1 || sudo useradd -m -s /bin/bash agent-admin
getent passwd agent-dev >/dev/null 2>&1 || sudo useradd -m -s /bin/bash agent-dev
getent passwd agent-test >/dev/null 2>&1 || sudo useradd -m -s /bin/bash agent-test

sudo usermod -aG agent-common agent-admin
sudo usermod -aG agent-common agent-dev
sudo usermod -aG agent-common agent-test

sudo usermod -aG agent-core agent-admin
sudo usermod -aG agent-core agent-dev
```

주의:

- 위 명령은 OrbStack Ubuntu Machine 안에서 실행한다. macOS 호스트에서 직접 실행하지 않는다.
- `groupadd -f`는 그룹이 이미 있으면 오류로 중단하지 않고 넘어간다.
- `getent passwd ... || sudo useradd ...`는 사용자가 없을 때만 생성한다.
- `usermod -aG`에서 `-a`를 빼면 기존 보조 그룹이 덮어써질 수 있으므로 반드시 `-aG`를 함께 사용한다.
- `agent-test`는 `agent-core`에 넣지 않는다. 테스트 계정은 민감 디렉터리 접근 대상이 아니기 때문이다.

## 명령어 설명

### 방법 1: 스크립트 실행 명령어

```bash
sudo bash scripts/setup-users.sh
```

- `sudo`: 사용자와 그룹 생성은 `/etc/passwd`, `/etc/shadow`, `/etc/group` 같은 시스템 계정 정보를 수정하므로 관리자 권한이 필요하다.
- `bash`: Bash 셸로 스크립트를 실행한다. 스크립트 파일에 실행 권한이 없어도 `bash scripts/setup-users.sh` 형태로 실행할 수 있다.
- `scripts/setup-users.sh`: B1-1 계정/그룹 생성 작업을 자동화한 스크립트 경로다.
- 이 스크립트는 이미 존재하는 사용자와 그룹은 건너뛰도록 작성되어 있어 여러 번 실행해도 최종 상태가 같게 유지된다.

### 방법 2: 직접 명령어 실행 설명

```bash
sudo groupadd -f agent-common
sudo groupadd -f agent-core
```

- `groupadd`: Linux 그룹을 생성하는 명령어다.
- `-f`: force 옵션이다. 같은 이름의 그룹이 이미 있으면 오류로 중단하지 않고 넘어간다.
- `agent-common`: `agent-admin`, `agent-dev`, `agent-test`가 모두 들어가는 공유 그룹이다.
- `agent-core`: `agent-admin`, `agent-dev`만 들어가는 핵심 운영 그룹이다.

```bash
getent passwd agent-admin >/dev/null 2>&1 || sudo useradd -m -s /bin/bash agent-admin
getent passwd agent-dev >/dev/null 2>&1 || sudo useradd -m -s /bin/bash agent-dev
getent passwd agent-test >/dev/null 2>&1 || sudo useradd -m -s /bin/bash agent-test
```

- `getent passwd <계정명>`: 해당 계정이 시스템에 존재하는지 확인한다.
- `passwd`: 비밀번호 자체가 아니라 사용자 계정 데이터베이스를 의미한다. 일반적으로 `/etc/passwd` 정보를 조회한다.
- `>/dev/null`: 정상 출력(stdout)을 화면에 표시하지 않고 버린다.
- `2>&1`: 오류 출력(stderr)도 정상 출력(stdout)과 같은 곳으로 보낸다. 여기서는 둘 다 화면에 보이지 않게 한다.
- `||`: 앞 명령이 실패했을 때만 뒤 명령을 실행한다.
- 따라서 `getent passwd agent-admin ... || sudo useradd ...`는 `agent-admin` 계정이 없을 때만 `useradd`를 실행한다는 뜻이다.
- `useradd`: Linux 사용자를 생성하는 명령어다.
- `-m`: 사용자 홈 디렉터리를 함께 생성한다. 예를 들어 `agent-admin`은 `/home/agent-admin` 홈 디렉터리를 가진다.
- `-s /bin/bash`: 로그인 셸을 `/bin/bash`로 지정한다. 사용자가 `su - agent-admin`처럼 로그인 세션을 열었을 때 Bash를 사용하게 된다.

```bash
sudo usermod -aG agent-common agent-admin
sudo usermod -aG agent-common agent-dev
sudo usermod -aG agent-common agent-test
```

- `usermod`: 기존 사용자 정보를 수정하는 명령어다.
- `-G agent-common`: 사용자를 `agent-common` 보조 그룹에 포함한다.
- `-aG`: append group의 의미로 이해하면 된다. 기존 보조 그룹을 유지하면서 새 그룹을 추가한다.
- `-a` 없이 `-G`만 사용하면 기존 보조 그룹 목록이 덮어써질 수 있으므로 위험하다.
- 세 계정을 모두 `agent-common`에 넣는 이유는 이후 `upload_files` 디렉터리를 공통 작업 공간으로 사용하기 위해서다.

```bash
sudo usermod -aG agent-core agent-admin
sudo usermod -aG agent-core agent-dev
```

- `agent-core`는 더 민감한 운영 리소스 접근용 그룹이다.
- `agent-admin`은 앱 실행과 운영 작업을 담당하므로 `agent-core`에 포함한다.
- `agent-dev`는 `monitor.sh`, 설정 스크립트 등 운영 스크립트를 관리해야 하므로 `agent-core`에 포함한다.
- `agent-test`는 테스트 계정이므로 `agent-core`에 포함하지 않는다.
- 이 구분 덕분에 이후 `api_keys`, `/var/log/agent-app` 같은 민감 디렉터리를 `agent-core` 그룹만 접근하도록 제한할 수 있다.

## 자주 발생하는 오류

- `Permission denied`: `sudo`로 실행해야 한다.
- 그룹에 추가했는데 `id`에 바로 안 보임: 로그인 세션을 다시 열어야 할 수 있다.
